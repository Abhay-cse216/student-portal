# Prompt Book — EduTrack Student Portal

## Project
**Title:** EduTrack – Student Portal
**Domain:** Education
**Purpose:** AI-assisted web application prototype for the ESE.

## Prompt 1 — Problem Definition
**Prompt:** Act as a software project analyst. Define a real-world problem in education that can be solved using a simple student portal. Identify users, objectives, pain points and basic requirements. Keep it suitable for a student web prototype.
**Purpose:** Select and define the problem.
**Improvement:** Asked the AI to keep the scope simple and focused on student academic activities.

## Prompt 2 — Feature Planning
**Prompt:** For an education student portal, suggest essential features for students. Include dashboard, courses, attendance, assignments, timetable, notices and profile. Explain what each feature should do.
**Purpose:** Create functional requirements.
**Improvement:** Removed complex features such as online payments and full university administration.

## Prompt 3 — UI/UX Design
**Prompt:** Design a clean, modern and responsive student portal interface. Suggest navigation, dashboard cards, typography, spacing, colors and mobile layout. Make it suitable for a university student.
**Purpose:** Plan the user interface.
**Improvement:** Requested a dashboard-first design with a fixed sidebar on desktop and responsive navigation on mobile.

## Prompt 4 — Code Generation
**Prompt:** Create a working student portal prototype using HTML, CSS and JavaScript. Include Dashboard, Courses, Attendance, Assignments, Timetable, Notices and Profile pages. Use realistic sample data, responsive design and interactive buttons. Provide separate files.
**Purpose:** Generate the first working prototype.
**Improvement:** Required all important functionality to work without a backend.

## Prompt 5 — Interactivity
**Prompt:** Add JavaScript interactions to the student portal: page navigation, assignment submission, add-assignment modal, course filtering, notice search, global search, profile editing, toast messages and dark mode. Do not remove existing features.
**Purpose:** Make the prototype functional.
**Improvement:** Requested client-side interactions using simple JavaScript.

## Prompt 6 — Responsive Testing
**Prompt:** Review the student portal for mobile responsiveness. Check sidebar navigation, dashboard cards, tables, forms, course cards and timetable. Suggest and implement CSS changes for phone and tablet screens.
**Purpose:** Improve usability on different screen sizes.
**Improvement:** Added breakpoints for 900px and 600px.

## Prompt 7 — Bug Fixing
**Prompt:** Test the assignment module. Verify adding an assignment, empty-field validation, submission status changes and pending-task count. Identify possible JavaScript errors and provide fixes.
**Purpose:** Fix important functionality.
**Improvement:** Added validation, status updates and user feedback messages.

## Prompt 8 — Final Review
**Prompt:** Act as a university project evaluator. Review this student portal prototype for completeness, usability, responsiveness, clear navigation and demonstration value. List important issues that should be fixed before an ESE demonstration.
**Purpose:** Final quality check.
**Improvement:** Ensured every requested module can be opened from the navigation and the main interactions can be demonstrated.

## Prompt Engineering Improvement Pattern
Initial prompts were broad. They were improved by specifying:
1. Role of the AI
2. Exact project domain
3. Target users
4. Required features
5. Technology constraints
6. Expected output
7. Testing criteria
8. Instruction not to remove existing functionality

## AI Tools Used
- Generative AI assistant for planning, code generation, debugging and improvement.
- Browser for manual testing of the generated prototype.
- VS Code for editing and running the files.

## Human Contribution
The student selected the domain, reviewed AI-generated suggestions, edited project content, ran tests, checked the interface and decided which AI-generated improvements to keep.
